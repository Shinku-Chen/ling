# 云端下发与"发布"的现状边界

> 写这份文档的原因：官方公开资料里没有"开发者自助上架小应用"的完整流程。
> 下面区分**已核实的事实**和**未核实的部分**，避免把猜测当结论。

## 1. 已核实：设备侧协议是公开的

Arcs-mini 固件仓库的 `docs/miniapp.md` 明确写了云端怎么把一个小应用送到设备上：

- 传输通道：MCP 的 `tools/call`，工具名 `ls.built_in.miniapp_install`；
- 六参数全必填：`id`、`version`、`name`、`url`、`size`、`hash`；
- `url` 是**有效期 300 秒**的裸 Lua 签名下载地址；`hash` 是 32 位小写 MD5；`size` 是准确字节数；
- 设备下载后在 PSRAM 里校验长度与 MD5，启动候选实例，成功才替换当前应用；
- 另有 `ls.built_in.miniapp_exit`（退出）与 `ls.built_in.get_device_capabilities`（能力查询）。

也就是说：**"实时更换小程序"就是这套下发机制**——云端每次推一个新 Lua，设备就换一个应用，
而设备不持久化任何源码。

## 2. 已核实：开发者现在能用的投放通道是 adb

LingClaw-SDK 官方 README 与 `docs/getting-started.md` 给出的开发者路径只有一条：

```sh
adb push counter.lua /miniapp/counter.lua
```

- 上传后立即运行、替换当前应用；源码不持久化，重启后要重新上传。
- 这条通道由固件的 `CONFIG_MINIAPP_ADB_DEBUG`（3.0.x 默认开启）提供。

## 3. 未核实：有没有开发者自助"上架/提交到云端"的入口

检索范围与结果（2026-10-02）：

| 查过的地方 | 结果 |
|---|---|
| LingClaw-SDK 仓库（README / docs / 本地 0.1.0 包全文） | 只有 adb 通道，没有任何"提交到云端/审核/上架"说明 |
| 官方文档中心（`ling wiki search` 全库关键词：小应用 / LingClaw / 发布 / 上架 / 模拟器 / 工单） | 未找到小应用发布流程；LS26 文档树里只有固件、外设、MCP 工具、烧录、常见问题 |
| `ling` CLI `1.0.1`（`ling app --help` 全部子命令） | 有应用/角色/唤醒词/知识库/OTA/MCP 等，**没有小应用相关命令** |
| 应用功能说明、配置应用介绍等文档 | 里面的"小程序"指**微信小程序（小聆助手/小聆AI）**，用于配网、角色与设备配置，**不是 LingClaw 小应用** |
| `platform.listenai.com` | 前端需登录，公开页面无法确认是否有小应用管理页 |

**结论（诚实版）**：目前公开资料能确认的是"小应用由云端下发、协议公开"，
但**没有**公开的"开发者自助上传到云端"流程。要落地这一步，需要向聆思确认：

- 咨询入口：LSCloud 工单 <https://cloud.listenai.com>（官方《提交工单》文档：注册 → 建组织 → 建项目 → 选"软件开发工单"）；
- 也可以先在自己的 `platform.listenai.com` 应用配置里确认有没有小应用管理页（我用的是未登录视角，看不到）。

## 4. 这对"希望出现在小应用界面里"意味着什么

| 你的目标 | 现在可行的做法 | 限制 |
|---|---|---|
| 在设备上跑自己的小应用（调试） | `tools/upload.ps1` 走 adb | 重启后消失，需要重新推 |
| 让设备"能实时换到我的应用" | 需要云端按第 1 节协议下发 | 公开资料没有自助上架入口，需与聆思确认 |
| 让应用在界面上看起来像"常驻功能" | 目前做不到（设备不存应用、没有应用列表页） | 想常驻属于固件定制（把功能做进固件或做端侧 MCP 工具） |

## 5. 不要做的事

- 不要顺着"登录后的网页内部接口"去构造 HTTP 请求替用户提交——平台侧写操作按官方文档走，
  涉及账号的操作用户自己做。
- 不要伪造签名 URL 或绕过 MD5/长度校验。
- 不要因为"云端下发走不通"就偷偷改设备固件分区或改官方固件行为；那属于端侧开发，
  需要独立的授权与流程。
